## What Happened

- Audited all eight skills with `skill-architect`; fixed findings across every skill, including two `discord-harvest` security defects (download-recipe shell injection, `?@`/`#@` URL allowlist bypass).
- Ported the dotfiles-held fixes into the repo: `init-rulebook` native-import loading and `localhost-screenshots` Playwright resolution from the project (with script-folder fallback).
- Made every skill Codex-ready: `agents/openai.yaml` per skill and descriptions with capability plus trigger in the first 120 characters. Verified with `codex debug prompt-input` (codex-cli 0.163.0).
- Refocused `figma-to-code` as a repo-convention layer that defers implementation to Figma's official `figma-design-to-code`; `code-to-figma` kept, with a retirement trigger if its plugin stays unpublished.
- Forward-tested six `init-rulebook` eval scenarios with fresh agents before its 1.0 promotion.
- Folded Dependabot PR #54 (CI action updates) into release PR #55.
- Squash-merged #55 as `3a4d183`; signed tag `v0.7.0`; GitHub release triggered npm publish. Verified npm 0.7.0 is `latest`, `gitHead` `3a4d183`, registry signatures and provenance attestations verified.
- Lifted the `init-rulebook` and `localhost-screenshots` refresh holds in dotfiles; installed `~/.agents/skills` copies match v0.7.0.
- Merged PR #56 (`ecb45c6`): `bin/drift-check.mjs` now compares skill versions with the release baseline (merge base with `main`, then the latest `v*` tag, then `HEAD^`), so correcting an unreleased draft bump passes push-event CI. Because `bin/` changed after `v0.7.0`, released skills4sh 0.7.1 (tag `v0.7.1` on `ecb45c6`; npm verified). Skills are unchanged from 0.7.0.

## Decisions Made

- Versions at release, each one step above the previous release: package 0.7.0; `init-rulebook` 1.0.0 and `eleventy-nunjucks` 1.0.0 (stable contract); `skill-architect` 1.1.0; `agent-memory` 2.8.0; `code-to-figma` 0.3.0; `discord-harvest` 2.1.0; `figma-to-code` 0.2.0; `localhost-screenshots` 3.5.0.
- Release PRs merge by squash; Dependabot updates pending at release time are folded into the release PR.
- Unreleased branches install with the `#ref` form (`t4sh/skills4sh#<branch>`); `tree/<branch>` URLs break on slash-containing branch names.
- Release only when installable content requires it: a change under `bin/` after a tag forces a package bump (bin/tag parity check); docs and `.agent-memory/` changes do not ship in the npm package and need no release.
